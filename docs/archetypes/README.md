## 1. 라우팅 표: 메시지 → Archetype

생성기는 리드 메시지에서 **"무엇을 비교하는가"**를 먼저 판별하고, 그다음 Archetype을 고른다. 판별 기준은 Zelazny의 비교 유형에 구조형·논증형을 더한 것이다.

| 리드 메시지가 말하는 것 | 신호 단어 (예) | 1순위 | 대안 |
|---|---|---|---|
| A가 B보다 크다 / 순위 | "가장 큰", "1위", "~보다 높다", "격차" | `bar-ranking` | `kpi-big-numbers` (항목 ≤3), `heatmap` (지표 여러 개) |
| 시간에 따라 변했다 (데이터 포인트 많음) | "증가", "감소", "추세", "~년 이후" | `line-trend` | `column-time-series` (시점 ≤8) |
| 전체 안에서 구성이 시간에 따라 변했다 | "비중이 커졌다", "믹스 변화" | `stacked-column` | `stacked-100` |
| 무엇이 합쳐져 총합이 되는가 / A에서 B로 가는 요인 | "요인", "기여", "브릿지", "갭" | `waterfall-bridge` | `stacked-100` (한 시점의 구성) |
| 둘 사이에 관계가 있다 | "~할수록", "상관", "비례" | `scatter-bubble` | — |
| 응답·분포가 이렇다 | "응답자의 N%", "대부분이" | `survey-bars` | `bar-ranking` |
| N개의 요소·축으로 이루어진다 | "세 가지", "4대 축" | `framework-pillars` | `text-columns` |
| 단계·순서로 진행된다 | "단계", "프로세스", "밸류체인" | `process-flow` | `timeline-roadmap` (날짜가 있으면) |
| 옵션·대상을 같은 기준으로 비교한다 | "옵션 비교", "A안 vs B안" | `comparison-table` | `harvey-ball-table` (정성 평가) |
| 해야 할 일 N개 | "~해야 한다", "레버", "과제" | `numbered-levers` | `initiative-one-pager` (과제 하나를 상세히) |
| 다른 곳에서는 이렇게 해서 성공했다 | "사례", "벤치마크" | `case-example` | — |
| 한 주장에 근거가 2~4개 | 제목에 절이 2개("~하고, ~하다") | `multi-chart-panel` | — |
| 정성 논증, 판단 | "가능성 낮음", "~때문" | `bullet-argument` | `text-columns` (대조) |
| 근거 없이 한 문장만 남기고 싶다 (섹션 전환, 핵심 주장, 마무리) | 주장 하나, 데이터 없음 | `statement` | `section-divider` (섹션 시작이면) |

**판별 규칙**
- 제목에 **절이 두 개**("X가 늘었고, Y는 줄었다")면 → `multi-chart-panel` 2분할 (E 묶음 관찰)
- 제목에 **개수 단어**("세 가지")가 있으면 → 시각 요소 개수를 그 숫자에 맞춘다
- 메시지가 **질문형**이면 → 답은 제목이 아니라 콜아웃·사이드바에 둔다

## 2. 공통 문법 규칙 (모든 장표에 적용)

5개 묶음 중 3개 이상에서 독립적으로 확인된 것만 넣었다.

### 제목
- **T1. 제목은 so-what 문장이다.** 주어와 서술어가 있는 완결된 판단 문장이어야 한다. 토픽 라벨("시장 현황")은 표지, 간지, 방법론, 부록, 참조표에만 쓴다.
- **T2. 길이는 2줄 이내.** 약 10~20단어 (중앙값 13.5, 90%가 21단어 이하).
- **T3. 제목 속 숫자는 장표에서 다시 보여야 한다.** 합계 막대, 강조 막대, 콜아웃, KPI, 합계 행 중 하나에 같은 숫자가 있어야 한다.
  근사치는 `~`로 쓴다. *(전 묶음 공통)*
- **T4. 제목이 지목한 항목만 강조색이고 나머지는 중립색이다.** 강조된 항목은 반드시 제목이 지목한 것이어야 한다.
- **T5. 개수 단어 = 시각 요소 수.** "세 가지 요인"이면 3열·3박스로 그린다.
- **T6. 시제와 서법.** 발견은 현재·과거형, 전망은 "~할 수 있다/~할 것", 권고 과제는 명령형·당위형으로 쓴다.
- **T7. 장 사이를 잇는 장치.** "그러나 / 또한 / 그 결과"로 시작하기, 말줄임표로 한 문장을 두 장에 걸쳐 쓰기, 연속 장표 표시 `(1/2)`.

### 장표 구조 (위에서 아래로)
```
┌──────────────────────────────────────────────┐
│ [tracker / section tag]               [sticker]│
│ 제목 (so-what, ≤2줄)                            │
│ 단위 줄: 지표, 단위, 기간 (회색, 작게)           │
├──────────────────────────────────────────────┤
│                                                │
│ 본문 (차트 / 표 / 다이어그램)  │ [takeaway 1/3] │
│                                                │
├──────────────────────────────────────────────┤
│ 각주 1, 2, 3                                   │
│ 출처: …                              [쪽번호]  │
└──────────────────────────────────────────────┘
```
- **L1.** 단위 줄은 제목 바로 아래에 둔다. 차트 장표에는 필수다.
- **L2.** 각주는 출처 바로 위, 출처는 좌하단. **우리 규칙(D5): 데이터가 있는 장표는 출처 필수(100%).**
- **L3.** 스티커는 우상단: `PRELIMINARY`, `NOT EXHAUSTIVE`, `ILLUSTRATIVE`, `ESTIMATE`.
  → **D5와 연결**: 출처가 없는 placeholder 데이터가 들어간 장표에는 자동으로 `ILLUSTRATIVE — 데이터 필요` 스티커를 붙인다.
- **L4.** 차트 + takeaway 사이드바 비율은 66:33. 사이드바에는 숫자가 들어간 결론 불렛 2~3개, 또는 큰 숫자 1개 + 문장 1개를 넣는다. 차트와 사이드바는 셰브런(›)으로 잇는다.

### 차트
- **C1.** 막대는 **값 내림차순 정렬**. 예외는 순서 자체에 의미가 있을 때(연도, 지역 순 등)다.
- **C2.** **막대 끝에 값 라벨을 달고 값 축은 없앤다.** 범례 대신 직접 라벨을 단다.
- **C3.** 합계·평균·기타는 **맨 끝에 다른 스타일**로 둔다.
- **C4.** 실적과 전망은 점선 세로선으로 나누고, 전망 구간은 색이나 패턴을 다르게 한다.
- **C5.** 재사용 가능한 마이크로 컴포넌트는 다음과 같다.
  - CAGR 화살표(`+4.2% p.a.`)
  - 증감 알약(`+8%p`, `2.3x`)
  - 축 아래 보조 지표 행
  - `100% = $X` 기준값
  - 축 절단 표시
  - 평균선·벤치마크선
  - 번호 마커 + 주석 목록
  - **점선 `?` 막대**: 모르는 값을 표시하는 데 쓰고, 우리 placeholder 표현에 그대로 쓴다
- **C6.** 차트는 **네이티브 차트**로 만들고, 라벨도 차트 데이터 라벨로 처리한다. 2013년 덱은 옛 방식 차트 위에 텍스트박스를 얹어 만들었는데, 그러면 편집할 때 깨지므로 따라 하지 않는다.

### 덱 구조 (Storyline)
- **S1. Exec Summary의 번호가 그대로 각 장 제목 앞 번호와 섹션이 된다.** 마지막 Key takeaways에서 요약을 반복해 처음과 끝을 맞춘다.
  → 처음 구상한 "exsum 불렛 = 후속 장 리드 메시지"가 실제 덱의 구조와 일치한다.
- **S2. 개요 장표가 ID(1, 2a, R1…)를 부여하고, 상세 장표 제목 앞에 같은 ID를 붙인다.** → Storyline spec에 `id`, `parent_id` 필드를 둔다.
- **S3. tracker는 목차를 반복하면서 현재 항목만 강조하는 방식이 기본이다.** 대안으로 제목 위 breadcrumb, 개요 그림 미니 썸네일이 있다.
  실제 덱에는 사람이 손으로 만든 tracker의 오류가 있었다. **생성기는 tracker를 spec에서 자동으로 만든다.**
- **S4. Backup은 지원하는 본 장표 바로 뒤에 `BACKUP:` 접두어로 붙이는 방식이 최근 추세다.** 별도 부록 섹션 방식도 있다.
- **S5. 병렬 챕터는 같은 템플릿과 같은 제목 구조를 반복한다.** 예를 들어 섹터별로 같은 장표 묶음을 만든다.

## 3. Archetype 목록

**Tier 1 = v1에 포함** (빈도가 높고 여러 덱에서 쓰인 것) · **Tier 2 = v1.x** · **Nav = 덱 뼈대**
`n` = 주 유형 장수 / 등장 덱 수 · 가중 비중 (v0.2, 203개 덱).

### 3.1 정량 차트

## 4. 이 카탈로그가 설계에 주는 것

1. **Storyline spec 필드**
   - 덱 구조: `id`, `parent_id`, `section`
   - 장표 내용: `lead_message`, `message_type`, `archetype`, `layout_variant`
   - 데이터와 출처: `data[]`(값, 출처, 발췌), `placeholders[]`
   - 표시 요소: `sticker`, `is_backup`
2. **QA 체크리스트**: T1–T5, L1–L3, C1–C3, S1–S3은 기계적으로 검사할 수 있다. 예: 제목 숫자가 차트에 있는가, 강조 항목이 제목에 있는가.
3. **렌더러 범위**: Tier 1은 정량 8종, 표 2종, 구조 5종, 텍스트 5종으로 총 **20종**이다. matrix-2x2와 issue-tree는 빈도는 낮지만 컨설팅을 상징하는 장표라 Brian 결정으로 v1에 포함했다. stacked-100은 v0.2 집계에서 waterfall보다 높게 나와 승격했다(2026-11-05). 마이크로 컴포넌트 8종(C5)과 레이아웃 변형 2종도 만든다.
4. **플로우 모드**: 메시지만으로 라우팅 표에서 Archetype을 고른다. 데이터 자리는 점선 `?` 막대와 `ILLUSTRATIVE` 스티커로 채운다.

## 5. 한계
- **표본:** 컨퍼런스 발표가 가장 많다. M&A·가격 전용 덱과 통신 덱은 여전히 거의 없다. 2008년 이전 덱은 11개다.
- **누락:** 다운로드 실패로 일본어 3개와 Stop TB가 빠졌다.
- **샘플링:** 긴 덱은 최대 12~30페이지만 뽑아서 봤다(최신 덱일수록 많이).
- **차단된 곳:** mckinsey.com 자체 덱, 일본 METI 등은 봇 차단으로 받지 못했다.
- **태깅 방식:** 태깅은 에이전트 5개가 공통 브리프로 나눠 했고, 사람이 검수하지 않았다. 묶음마다 경계 사례(예: comparison-table과 data-table)를 다르게 분류했을 수 있다.
